Persistence Runtime, Explained

This module connects the Writer Agent graph to Postgres, assigns each workflow a durable thread identity, resumes interrupted execution, and exposes checkpoint inspection without putting database logic in graph nodes.

The mental model

persistence.py is the runtime boundary between application calls, LangGraph execution, and checkpoint storage. It does not decide how the supervisor plans or how specialists write.

Caller thread ID + workflow input
→
PersistentWriterAgent lifecycle + safety checks
→
PostgresSaver graph checkpoints + history

It owns

Postgres connection, saver setup, graph compilation, and cleanup.

It delegates

Actual workflow transitions to the compiled supervisor graph.

It protects

Thread identity, new-run boundaries, and missing-resume checks.

thread_config()

This helper converts an application thread ID into the exact config shape LangGraph expects. Postgres uses that ID to group checkpoints into one execution history. 

def thread_config(
    thread_id: str,
    metadata: Mapping[str, Any] | None = None,
) -> RunnableConfig:
    if not thread_id or not thread_id.strip():
        raise ValueError("thread_id must be a non-empty string")

    config: RunnableConfig = {
        "configurable": {"thread_id": thread_id.strip()},
    }
    if metadata:
        config["metadata"] = dict(metadata)
    return config

Input normalization

Leading and trailing whitespace is removed. Empty or whitespace-only identifiers fail immediately.

Metadata copy

A new dictionary prevents the runtime config from retaining the caller's mutable mapping object.

Two metadata locations: config metadata is attached to checkpoints by LangGraph. The runtime also stores run_metadata inside SupervisorState for direct application access.

PersistentWriterAgent.__init__()

Construction creates a ready-to-run persistent graph. It performs connection and migration work immediately, so failures happen before the first workflow request.

  1. Resolve the database URL. The explicit argument wins; otherwise the runtime reads DATABASE_URL.
  2. Reject missing configuration. A clear ValueError replaces a less useful low-level connection error.
  3. Open the Psycopg connection. The connection uses autocommit and dictionary rows.
  4. Create and initialize the saver. setup() creates or migrates checkpoint tables.
  5. Compile the supervisor graph. The saver and optional interrupt boundaries are injected into LangGraph. 
resolved_url = database_url or getenv("DATABASE_URL")
if not resolved_url:
    raise ValueError(
        "DATABASE_URL is required for Postgres checkpointing."
    )

self._connection = psycopg.connect(
    resolved_url,
    autocommit=True,
    row_factory=dict_row,
)
self.checkpointer = PostgresSaver(self._connection)
self.checkpointer.setup()
self.graph = build_supervisor_graph(
    checkpointer=self.checkpointer,
    interrupt_before=interrupt_before,
    interrupt_after=interrupt_after,
)

Why autocommit=True

Saver schema migrations and checkpoint writes are committed without requiring transaction management in this runtime.

Why dict_row

The saver accesses query results by column name. Default tuple rows do not satisfy that contract.

start(): create a new thread

Starting is intentionally different from resuming. It accepts new workflow input and refuses to run if the chosen thread already has a checkpoint. 

config = thread_config(thread_id, metadata)

if self.graph.get_state(config).values:
    raise ValueError(
        f"Thread {thread_id!r} already exists; use resume() or a new ID."
    )

run_metadata = {
    "started_at": datetime.now(UTC).isoformat(),
    **dict(metadata or {}),
}
initial_state: SupervisorState = {
    **state,
    "thread_id": thread_id.strip(),
    "run_metadata": run_metadata,
}
return self.graph.invoke(initial_state, config=config)
Operation Reason
Read existing state first Prevents a new user request from contaminating an older thread.
Add UTC start time Gives each run a stable, timezone-independent creation timestamp.
Merge caller state Preserves fields such as user_id and user_request.
Invoke with initial state Signals a new graph execution rather than a continuation.
Important invariant: one new workflow request gets one new thread ID. Reusing an ID is not an update operation.

resume(): continue existing work

Resume finds the latest checkpoint for a thread and invokes the graph with no new state. LangGraph continues from the pending node recorded in the snapshot. 

config = thread_config(thread_id, metadata)
snapshot = self.graph.get_state(config)

if not snapshot.values:
    raise KeyError(
        f"No checkpoints found for thread {thread_id!r}."
    )

return self.graph.invoke(None, config=config)
First process
Calls start(); graph stops after an interrupt.
Postgres
Retains state values, next node, pending writes, and checkpoint ancestry.
Later process
Calls resume() with the same thread ID.
LangGraph
Loads the latest snapshot and executes the recorded next node.
Passing None is deliberate. Passing another state dictionary would represent new input and could alter the saved workflow instead of continuing it.

Inspection methods

get_state(thread_id)

Returns the newest StateSnapshot. Useful fields include values, next, tasks, and checkpoint metadata.

get_history(thread_id)

Materializes all snapshots into a newest-first list for debugging, audit trails, and state-transition analysis. 

snapshot = agent.get_state("report-rag-001")
print(snapshot.values["status"])
print(snapshot.next)

history = agent.get_history("report-rag-001")
for checkpoint in history:
    print(checkpoint.metadata["step"], checkpoint.next)
History is converted to a list for a simple API. For very long-running workflows, exposing the underlying iterator or adding pagination would reduce memory usage.

Connection cleanup

The class supports explicit cleanup and Python's context-manager protocol. close() is idempotent, so calling it more than once does not close an already closed connection again. 

def close(self) -> None:
    if not self._closed:
        self._connection.close()
        self._closed = True

def __enter__(self) -> PersistentWriterAgent:
    return self

def __exit__(self, *_: object) -> None:
    self.close()
Prefer with PersistentWriterAgent() as agent:. It closes the connection on normal completion and when an exception leaves the block.

Configuration versus workflow state

Concept Example Responsibility
Runtime configuration DATABASE_URL Tells the runtime where Postgres is located.
Runnable configuration configurable.thread_id Tells LangGraph which checkpoint history to read and write.
Checkpoint metadata source, step, writes Describes how a specific graph snapshot was produced.
Workflow state request, subtasks, status, final answer Contains the domain data nodes read and update.
Run metadata started time, request source Application-visible context saved inside workflow state.

Complete usage example

from writer_agent import PersistentWriterAgent

thread_id = "report-rag-001"

with PersistentWriterAgent() as agent:
    result = agent.start(
        thread_id,
        {
            "user_id": "user_001",
            "user_request": "Write an overview of RAG.",
        },
        metadata={"request_source": "cli"},
    )

# Later, possibly in a new process:
with PersistentWriterAgent() as agent:
    snapshot = agent.get_state(thread_id)
    if snapshot.next:
        result = agent.resume(thread_id)
    else:
        result = snapshot.values

print(result["status"])
Calling resume() on a completed thread simply has no pending node to advance. Checking snapshot.next makes caller intent explicit.

Failure behavior

Condition Result Caller action
Missing database URL ValueError during construction Set DATABASE_URL or pass it explicitly.
Postgres unavailable Psycopg connection exception Check container health, network, credentials, and TLS settings.
Blank thread ID ValueError Generate or provide a stable non-empty identifier.
Start with existing thread ValueError Call resume() or use a new thread ID.
Resume unknown thread KeyError Verify the ID or start a new workflow.

How the integration test proves durability

  1. Create a unique thread. A UUID prevents collisions with checkpoints from earlier test runs.
  2. Interrupt after initialization. The snapshot records supervisor_plan as the next node.
  3. Reject duplicate start. The same thread cannot accept a different request.
  4. Close the first Postgres connection. This proves continuity does not depend on process memory.
  5. Open a second connection and resume. The original task ID survives and execution reaches the expected state.
  6. Inspect checkpoint history. Multiple snapshots confirm that execution steps were persisted.
The test verifies the important boundary: durability across independent database connections, not just repeated calls on the same Python object.
